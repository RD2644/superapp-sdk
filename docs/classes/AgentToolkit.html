    Class AgentToolkit

    Exposes SDK capabilities as tools that an in-app AI assistant can call.

    Remarks

    Intended for assistants that run inside a MiniApp, on behalf of the signed-in user. It does not call native code itself; it wraps LoyaltyModule and CheckoutModule with input validation suited to model-generated arguments, a mandatory user confirmation before checkout, a permission check via ScopeModule, and a telemetry hook.

    Tool calls never throw. Like the rest of the SDK, they resolve to a response with a status_code, which you can pass back to the model as the tool result.

    Example

    import { AgentToolkit } from '@grabjs/superapp-sdk';

    const toolkit = new AgentToolkit({
      confirmCheckout: (summary) => showConfirmDialog(summary),
      prepareCheckout: (summary) => myBackend.createGrabPayTransaction(summary),
    });

    // Pass toolkit.tools to your LLM, then route each tool call back:
    const result = await toolkit.call(toolCall.name, toolCall.arguments);

          name: "estimate_rewards",
          args: unknown,
      ): Promise<AgentEstimateRewardsResponse>

      Runs a tool requested by the agent.

      Parameters

      • name: "estimate_rewards"

        Tool name from AgentToolkit.tools.

      • args: unknown

        Tool arguments as produced by the model. Validated before use.

      Returns Promise<AgentEstimateRewardsResponse>

      This method can return the following status_code values:

      • 200 (OK): The tool ran. estimate_rewards returns an AgentEstimateRewardsResult; trigger_checkout returns the TriggerCheckoutResult from native checkout.
      • 204 (No Content): The user declined the checkout confirmation.
      • 400 (Bad Request): Invalid arguments. The error explains why, so the model can retry.
      • 403 (Forbidden): The MiniApp lacks the required permission.
      • 404 (Not Found): Unknown tool name.
      • 424, 426, 500, 501: Passed through from the underlying module.
